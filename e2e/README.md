# 브라우저 검증 (e2e)

헤드리스 크롬을 CDP 로 직접 구동해 실제 브라우저에서 앱을 검증한다.
전용 테스트 러너 의존성이 없고 Node 내장 `WebSocket` 만 쓴다.

```bash
npm run e2e              # 전체 실행
npm run e2e -- word      # 이름이 word 를 포함하는 스펙만
npm run test:unit        # 순수 함수 단위 테스트 (92건)
```

`npm run e2e` 는 빌드 → preview 서버 기동 → 크롬 기동 → 스펙 실행 → 정리의 순서로
동작하고, 실패가 있으면 종료 코드 1 을 돌려준다.

## 왜 이게 있는가

React `key` 충돌, 대소문자 충돌, 문장 인덱스 밀림처럼 **조용히 실패하는** 버그가
실제로 세 건 있었다. 단위 테스트로는 잡히지 않았고 매번 손으로 띄운 스크립트로만
찾았다. 여기서는 같은 시나리오를 고정해 회귀를 막는다.

각 스펙은 `Storage.clearDataForOrigin` 으로 localStorage 와 IndexedDB 를 지우고
첫 실행 상태에서 시작한다. 그래서 서로의 데이터를 물려받지 않는다.

## 스펙

| 파일 | 다루는 것 |
|---|---|
| `01-documents` | 온보딩 → 본문 입력 → 문서 열람, 글자 보존, 통계 정확성, 등장 기록 |
| `02-word-status` | ○◐● 상태와 색상, 전역 반영, 새로고침 후 복원, `US`/`us` 상태 독립 |
| `03-sentence-translation` | 단어 팝오버 vs 문장 팝오버, 드래그 번역, 앱 언어 전환, en→en identity |
| `04-dictionary` | 한국어 활용형 정의, 기본형 항목, 미탐색 안내, 다항 품사, 출처 표기 |
| `05-inflection` | de/es/fr 활용형 → 기본형, 독일어 명사 대소문자 |
| `06-occurrences` | 등장 기록, `US`/`us` 분리, `The`/`the` 병합, 문맥 문장 |
| `07-theme-layout` | 테마 10종 대비(WCAG) 검증, `theme-color` 동기화, 반응형 네비 |

## 실패가 조용하지 않게

- **콘솔 오류·경고를 스펙 실패로 센다.** React `key` 충돌 경고가 여기서 잡힌다.
- 스펙이 예외를 던져도 나머지 항목은 실행하고, 마지막 요약에 개수가 찍힌다.

## 한계

- 번역·사전 스펙은 **실제 Supabase Edge Function 과 네트워크를 쓴다.**
  오프라인에서는 `04`·`05` 가 실패한다.
- 헤드리스 크롬이 있어야 한다 (`google-chrome`).
